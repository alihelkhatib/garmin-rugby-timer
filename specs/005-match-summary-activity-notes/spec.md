# Feature Specification: Match Summary in Garmin Connect Activity Notes

**Feature Branch**: `005-match-summary-activity-notes`  
**Created**: 2026-03-10  
**Status**: Draft  
**Input**: User description: "create a new feature specification that generates a match summary including scores for both teams, cards, and other similar aspects and places them in the notes for the activity in the garmin connect"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Match Summary Embedded in Activity (Priority: P1)

A referee finishes a match and saves the game on their Garmin watch. Later that day, they open Garmin Connect on their phone and navigate to the activity recorded during the match. In the activity's notes or description field they can read the full match result: final scores, try counts, yellow and red card discipline, penalty counts, match duration, and format (7s or 15s) — all without needing to separately export an event log or recall the game from memory.

**Why this priority**: This is the core deliverable. All data the app already tracks is captured at game-end and written into the activity record so it travels automatically with every synced session. No additional user action is required after saving the game.

**Independent Test**: Can be fully tested by completing a full match (with at least one try, one yellow card, and one penalty recorded), saving the game, syncing to Garmin Connect, and verifying the activity notes field contains the correctly formatted summary.

**Acceptance Scenarios**:

1. **Given** a match has been played with scores, tries, cards, and penalties recorded, **When** the referee saves the game on the watch, **Then** a structured match summary is automatically embedded in the activity description when the activity syncs to Garmin Connect.
2. **Given** the match summary is generated, **When** it is viewed in Garmin Connect, **Then** it shows at minimum: final score for each team, try count for each team, yellow card count per team, red card count per team, penalty count per team, total match duration, and game format (7s or 15s).
3. **Given** team names have been set (per spec 003), **When** the summary is generated, **Then** it uses those team names in place of "Home" and "Away."
4. **Given** no team names have been set, **When** the summary is generated, **Then** it uses "Home" and "Away" as the team identifiers.
5. **Given** a match ended with no cards or penalties, **When** the summary is generated, **Then** those sections show zero — the summary must not show stale or null values.

---

### User Story 2 - On-Watch Summary Preview (Priority: P2)

Immediately after saving the game, the referee can view a formatted summary on the watch screen before the phone syncs. This gives them immediate confirmation of what was recorded and lets them verbally confirm the result with the teams while still on the pitch.

**Why this priority**: Useful pitch-side confirmation, but the activity notes in Garmin Connect remain valuable even without this. Building on the same generated summary content from Story 1 means minimal additional effort.

**Independent Test**: Can be fully tested by completing a match, triggering the save action, and verifying the summary screen appears on the watch with correct data — completely independent of Garmin Connect sync.

**Acceptance Scenarios**:

1. **Given** the referee confirms "Save Game" in the end-game dialog, **When** the game is saved, **Then** a summary screen is displayed on the watch showing the match result.
2. **Given** the summary screen is displayed, **When** the referee scrolls through it, **Then** all the same data fields included in the Garmin Connect notes are visible.
3. **Given** the summary screen is displayed, **When** the referee presses Back or a dismiss button, **Then** the app returns to the idle/ready state.

---

### User Story 3 - Summary Header in Event Log Export (Priority: P3)

When the referee exports the event log (via the existing BACK/LAP menu), the exported text is prefixed with the match summary block, so any external recipient (coach, administrator) immediately sees the headline result at the top rather than having to read through all timestamped event entries.

**Why this priority**: Enhances the existing export feature with minimal additional work since the summary content is already generated by Story 1.

**Independent Test**: Can be fully tested by completing a match, using "Save log" from the event log menu, retrieving the exported text from storage, and confirming the summary header appears before the event entries.

**Acceptance Scenarios**:

1. **Given** a match has been saved and the event log export is triggered, **When** the exported text is retrieved, **Then** the first section is the match summary block and timestamped event entries follow below it.
2. **Given** the exported text is read, **When** the summary block is examined, **Then** it contains the same fields as the Garmin Connect activity notes.

---

### Edge Cases

- What happens when the match is abandoned (game saved mid-match rather than at full time)? The summary MUST clearly indicate the match did not reach full time and show the score and duration at the point of abandonment.
- What happens when no events were recorded (e.g., a test run ended immediately)? The summary is still generated with zero values; no field should be omitted purely because its value is zero.
- What happens if the summary text exceeds the maximum length supported by the Garmin Connect activity notes field? The summary is truncated gracefully, with the most important fields (final score, tries, cards) positioned first so they survive any truncation.
- What if GPS/activity recording was not started (e.g., the watch model does not support it)? The on-watch summary preview (Story 2) and event log prefix (Story 3) still function; only the Garmin Connect embedding is skipped with a silent fallback — no crash or error is shown to the user.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The app MUST generate a structured match summary at the point the game is saved, containing: final score (home and away), tries (home and away), yellow card count (home and away), red card count (home and away), penalty count (home and away), total elapsed match duration, and game format (7s or 15s).
- **FR-002**: The match summary MUST be embedded into the saved GPS/activity recording so that it appears in the activity description or notes field in Garmin Connect after the activity syncs.
- **FR-003**: The match summary MUST use team names from persistent storage, defaulting to "Home" and "Away," consistent with planned team-name support (spec 003).
- **FR-004**: If the match ends without reaching full time (abandoned), the summary MUST include a visible indicator that the match was not completed and show the score at the point of saving.
- **FR-005**: The on-watch end-of-game flow MUST display the generated summary as a readable screen that the referee can scroll through immediately after saving, before any phone sync occurs.
- **FR-006**: The summary screen on the watch MUST be dismissable via a back or confirm gesture, returning the app to the idle/ready state without data loss.
- **FR-007**: The event log export text MUST be prefixed with the match summary block when the "Save log" action is used, with event entries following after a clear separator.
- **FR-008**: Summary generation MUST handle zero values (e.g., no cards, no penalties) without displaying null, undefined, or blank fields — every field MUST show a valid value or explicit zero.
- **FR-009**: If the generated summary text exceeds the maximum field length supported by the activity record, the system MUST truncate at a sensible word or line boundary and MUST NOT cause a crash or corrupt the activity record.
- **FR-010**: Summary generation and activity embedding MUST be triggered automatically at game-save time with no additional user action required beyond the existing "Save Game" confirmation.

### Key Entities

- **Match Summary**: A structured text block produced at game-save time, containing the final state of all tracked match statistics (scores, tries, cards, penalties, duration, format). Used for the Garmin Connect activity description, the on-watch preview screen, and the event log export header.
- **Activity Record**: The GPS/sport recording session created on match start and saved on match end. The match summary is attached to this record as a description or notes payload before it is saved and synced to Garmin Connect.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: After saving a match and syncing to Garmin Connect, all recorded statistics (scores, tries, cards, penalties, duration, format) are present and accurate in the activity notes — verifiable by direct comparison with the event log.
- **SC-002**: The match summary is generated and visible on the watch within 3 seconds of the referee confirming "Save Game."
- **SC-003**: A referee can read the headline result (scores and try counts for both teams) from the on-watch summary screen without scrolling — the most critical fields appear in the first visible screen area.
- **SC-004**: The event log export, when reviewed by a third party (e.g., a coach), makes the final result immediately identifiable at the top without reading through timestamped event entries.
- **SC-005**: Summary generation introduces no new crash paths — the app saves the activity and transitions to idle state correctly even when all discipline counts are zero and no GPS session was active.

## Assumptions

- The Garmin Connect IQ `ActivityRecording.Session` API or the `FitContributor` API provides a mechanism to attach free-text metadata to a saved activity FIT file that Garmin Connect surfaces in the activity detail view. The specific API support must be confirmed during planning; if no direct notes field is available, a FIT custom data contribution approach will be evaluated as a fallback.
- The existing `finalizeGameData` function in `RugbyTimerPersistence.mc` already captures all statistical data required for the summary; no new model fields are needed — only a formatting and write step is added.
- The maximum text length for an activity description in Garmin Connect is assumed to be at least 500 characters, sufficient for the planned summary format; this must be confirmed during implementation.
- The on-watch summary screen reuses the existing `WatchUi` view stack (similar to the existing `EventLogMenu`); no new UI framework components need to be introduced.
- Team name support from spec 003 may not be implemented before this feature; this spec assumes graceful degradation to "Home"/"Away" defaults when team names are not stored.
