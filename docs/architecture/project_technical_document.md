# Project Technical Document

## Overview
- Repository: `rugby-timer`
- Language: Monkey C (Garmin Connect IQ)
- Target platforms: compiler-validated Garmin fēnix 6/7/8/E families plus vívoactive 5/6, with related tactix/quatix/Enduro variants covered where Garmin maps them onto the same Connect IQ product ids.
- Purpose: Rugby match timing, scoring, discipline tracking, GPS `SPORT_RUGBY` recording, overlay dialogs for conversions/penalties, event-logging, and data persistence/export.

## Architecture
- `source/` is now lightly organized by role: top-level files remain the main app/runtime/service modules, `source/support/` holds pure shared rule/math/key helpers, and `source/types/` holds typed adapter/value-wrapper files used at module boundaries.
- `RugbyTimerApp.mc`: App entry point and provider for the main view/delegate pair.
- `RugbyTimerApp.mc`: App entry point and provider for the main view/delegate pair. It now ensures the shared `RugbyGameModel` is initialized once and reused across both the settings entrypoint and the main match screen so preset/custom-profile changes are not lost during app/view startup.
- `RugbyTimerDelegate.mc`: Handles button presses and menu entries, including idle half-length adjustments on UP/DOWN, a held `UP/MENU` shortcut into the preset picker, BACK/LAP menu items (`Event Log`, `Save Game`, `Reset Game`), and delegating to the overlay/timing helpers.
- `RugbyTimerView.mc`: Central orchestrator that wires the helper modules, triggers UI updates, and keeps gameplay state (scores, conversions, card timers, GPS tracking, persisted summaries) in sync without showing a startup game-type prompt.
- `RugbyTimerViewSupport.mc`: Pure presentation-rule helper for `RugbyTimerView`; it owns overlay visibility reconciliation, main-screen hint-mode selection, and toast visibility rules so those decisions are testable outside WatchUi.
- `RugbyTimerRenderer.mc`: Computes layout offsets for the scoreboard (`baseTimerY`, `candidateTimerY`, half/state text, card stack positions) and draws the card timers, countdown/game clocks, and overlay background so the view can remain lean. The main match screen now uses a measured layout pass based on actual font heights and live card-row count rather than only fixed percentages, which gives the large countdown, side-column card timers, and paused/state text their own vertical bands on round Fenix displays. The top score band now applies a round-watch safe-area rule before rendering side labels: non-default label presets are drawn only if they fit within the circular shoulder bounds, otherwise they are compacted or suppressed instead of clipping. The center metadata stack also uses measured font heights so `Half 1` and the tries row keep a readable gap on smaller round devices instead of overlapping.
- `RugbyTimerRenderer.mc`: The card-stack rendering path is now internally deduplicated through small helper methods for timed card entries and permanent red-card rows, backed by typed render-helper models instead of ad hoc dictionaries. The home/away yellow/red branches no longer each maintain separate copies of the same draw logic, and the renderer cleanup keeps the build free of the temporary container-analysis warnings introduced during the first pass.
- `RugbyTimerTiming.mc`: Runs the shared `onUpdate` loop and advances three separate clocks: `elapsedTime` (always-on match elapsed), `gameTime` (the pauseable match clock that drives the half countdown and special timers), and `suspensionTime` (the pauseable sanction clock that drives yellow/red timers while still running through halftime). It also emits event-specific haptics (half warning, start/pause/resume, pause reminders, lock, conversion/penalty warnings and expiry, yellow warnings and expiry).
- `RugbyTimeMath.mc`: Centralizes numeric guards, delta-second calculations, countdown clamping, forward/reverse clock snapshots, and short card-timer formatting so the live update loop, pause-sync path, and persistence layer all use the same clock math.
- `RugbyMatchStateSupport.mc`: Centralizes pure state-classification and transition-decision rules such as which states run clocks, which live states restore as paused snapshots, what `SELECT` should do in each state, and when scoring should launch conversion/penalty phases. The side effects still live in the existing services; this helper only prevents those rule checks from drifting apart.
- `RugbyClockService.mc`, `RugbyScoringService.mc`, `RugbyDisciplineService.mc`, `RugbyRecordingService.mc`, `RugbySnapshotService.mc`: Internal helper services that now hold most of the state-transition, scoring, discipline, recording, and snapshot orchestration logic. `RugbyGameModel.mc` remains the public facade, but the behavior is now grouped by responsibility so future changes do not pile more branches into one file.
- `RugbyTimerCards.mc`: Tracks yellow/red timer dictionaries per team, preserves `Y#` and `R#` labels as new sanctions are added, and derives live sanction countdowns directly from `suspensionTime` using the same second units as the main clocks. This avoids the old seconds-vs-milliseconds mismatch that made sanctions drift or appear stalled.
- `RugbyTimerOverlay.mc`: Renders the conversion/penalty overlay screen with prompts (UP = success, DOWN = miss) plus countdown text, confirmation message, and ensures the main countdown label stays white while the special timer matches the overlay color.
- `RugbyTimerPersistence.mc`: Saves/restores game state (`gameStateData`, `eventLog`, `lastGameSummary`), snapshots `elapsedTime`, `gameTime`, `suspensionTime`, derived countdown values, and sanction clock baselines, reopens live saved matches as paused resumable state, clears cards on reset/finish, records totals per color/team, wires the “Save log” action to Storage, discards malformed saved snapshots instead of partially restoring bad data, and is now internally split into `buildSnapshot` / `applySnapshot` phases with smaller restore helpers so schema changes and round-trip tests stay safer.
- `RugbyTimerEventLog.mc` plus `EventLogEntry.mc`: Format timestamped entries (`HH:MM – Home Try`) into `lastEvents` and expose the log view so referees can export it via the Exit dialog without adding more raw dictionary shaping at the UI boundary.
- `RugbySettingsMenu.mc`, `RugbySettingsNavigation.mc`, `RugbySettingsPickers.mc`, plus `RugbySettingsSupport.mc`: Own the idle-only setup menus for the live editable ruleset: match format, team labels, conversion/penalty timers, overlays, theme, and reset behavior. Half length is adjusted directly from the idle main screen rather than through a duplicate settings row. The built-in match-format chooser now exposes the short `7s`, `10s`, `15s`, and `U19s` labels directly, while settings continue to edit the current rules and persist those values for the next launch. The settings root now reads its displayed values directly from the active model whenever the app is running. Submenu selections and timer picks now apply directly to that same live model, pop back one level, refresh the same root menu in place, and restore focus to the row that launched the submenu. That keeps the visible format, timer rows, overlay toggles, and team-label mode aligned with the actual current state on-device. The submenu and timer-picker rows now use plain string item identifiers instead of symbol ids so selection handling stays consistent on-device. Inline toggle rows now update their visible `On`/`Off` state in place so the focused row stays put instead of bouncing back to the top of the menu.
- `RugbyMatchProfiles.mc`: Defines the preset rule packs, migrates older `rugby7s`/per-type duration storage into the new `matchProfileId` + `Custom` profile model, and preserves user-edited custom values, including the custom profile label, separately from the built-in presets. The built-in preset list now surfaces directly in settings as `Rugby 7s`, `Rugby 10s`, `Rugby 15s`, and `U19`.
- `RugbyTeamIdentitySupport.mc`: Resolves the preset-backed home/away label pairs used by settings, the score renderer, event-log wording, and finalized summaries. It now also exposes compact score-band aliases (`1st`/`2nd`, `V`/`JV`, `R`/`B`, etc.) for small round-watch layouts. The implementation intentionally avoids free-form text entry so setup stays practical on five-button watches like the fēnix 6.
- `MatchProfileEntry.mc`, `ScoreEvent.mc`, `CardEntry.mc`: Typed wrappers around the most common stored/runtime dictionary shapes used in the recent refactors. `MatchProfileEntry` now also carries the preset-backed `teamLabelMode` presentation field. These wrappers are still adapters over the existing schemas, not a persistence-format redesign.
- File-organization note: the typed wrappers/adapters now live under `source/types/`, and the pure shared helpers (`RugbyTimeMath`, `RugbyMatchStateSupport`, `RugbyStorageKeys`) now live under `source/support/`. This keeps the main `source/` listing focused on app/runtime/service files without changing class names or behavior.
- `RugbyTimerMenus.mc`: Holds the main match menu, score/card dialog menus, exit menu delegate, and event-log menu classes so `RugbyTimerDelegate.mc` can stay centered on hardware input behavior.
- `RugbyTimerInputSupport.mc`: Holds the pure input rules used by `RugbyTimerDelegate`, including idle half-minute clamping, overlay key-to-action mapping, and hold-to-preset key gating, so those behaviors can be unit-tested without the watch runtime.
- `PersistedGameSnapshot.mc`, `PersistedCardTimerEntry.mc`, `PersistedStatePair.mc`, `RugbyTimerRenderTypes.mc`: Typed adapters for the older persistence/render paths. These keep snapshot storage, serialized sanction timers, timer-update results, and renderer layout/font/card-info values off raw dictionaries in the newly cleaned code paths.
- `RugbyStorageKeys.mc`: Centralized storage-key definitions shared by persistence, settings, profile migration, and tests so Storage schema changes do not require string hunting across the repo.
- `MatchSummaryEntry.mc`: Typed adapter for finalized `lastGameSummary` payloads so persistence and tests can work with the post-match summary without raw dictionary indexing. Finalized summaries now also store the resolved home/away labels used during the match.
- `scripts/validate-local.sh`: One-command local validation wrapper that builds the app target and the Garmin unit-test target before optionally handing off to the simulator test script.
- Low-risk cleanup note: several obsolete helper methods that no longer participated in production or test flows were removed from the renderer, persistence adapter, view, cards helper, and model facade to reduce surface area without changing runtime behavior.

## File Naming and Documentation Notes
- Current naming is intentionally split by role:
  `Rugby*Service` files are non-UI orchestration/business-logic helpers, while most `RugbyTimer*` files are view/runtime/UI helpers tied to the watch app flow.
- That convention is not perfectly universal yet, but it is consistent enough to preserve for new files.
- There are no obvious dead `.mc` files remaining after the refactor passes; the small wrapper files are deliberate boundary types, not accidental fragmentation.
- All current `.mc` files now include a top-of-file purpose preamble so a maintainer can quickly see why each file exists before reading the implementation.

## Layout Math Notes
- `baseTimerY` defines the preferred vertical anchor for the big clocks (game timer at the top, countdown below when overlay inactive). `candidateTimerY` is a computed Y coordinate that moves up/down to avoid overlapping with the card stack; the renderer clamps the final `countdownY` between `countdownMin` and `countdownLimit`.
- `stateY` and `hintY` define where the “Half #” text, tries indicator, and hint text reside. The renderer shifts these downward whenever the countdown climbs into the card stack zone so the timers and card displays never overlap.
- Card timers start at `cardsY` and push down incrementally in simple home/away columns centered under each score lane (`width / 4` and `3 * width / 4`). Each new sanction for the same team is appended below the previous one, which keeps the stack order predictable (`Y1`, `Y2`, `R1`, `R2`) and easier to verify on-watch.
- The overlay keeps the main countdown visible near the top and the special timer centered, preventing the red conversion text from touching the scoreboard. On the base match screen, the renderer now measures the active fonts and card rows to place the main countdown and lower text bands automatically instead of relying on percentage nudges alone. The idle guidance remains split into short, centered safe-area lines (`UP/DOWN set`, `SELECT start`) rather than one long sentence pushed into the bottom bezel.
- A small play/pause icon anchors near the top-left (`iconY = height * 0.04` with an ~8% horizontal inset), reflecting the current game state, and a lock icon sits near the top-right above the scores when the UI is locked.

## Key Behaviors
- Idle setup: the app now opens directly on the main timer screen, the referee can adjust half length immediately with UP/DOWN, and a held `UP/MENU` press opens a direct `Match Preset` picker for Rugby 7s, 10s, 15s, U19, and the saved `Custom` preset without routing through the heavier settings stack. Presets are now applied after the picker closes, which forces the idle countdown to snap visibly to the selected format on-device.
- Resume behavior: when the app is reopened during a live match, the saved state returns as a paused snapshot with the prior live state kept in `pausedState`. The count-up clock stays frozen on launch and only resumes once the referee explicitly restarts play, preventing the game timer from advancing in the background.
- Reset behavior: live match initialization/reset is now centralized in `RugbyGameModel.resetMatchRuntimeState()`, so startup and manual reset share one canonical baseline for clocks, sanctions, event history, and recording status fields.
- Event persistence: scoring/card events now write a fresh snapshot immediately instead of waiting for the 5-second autosave window, so a just-recorded try, card, or conversion is still there if the app is closed right after the button press.
- Test workflow: the Garmin unit-test target must be built with `--unit-test`; `scripts/run-tests.sh` now does this explicitly so the SDK keeps the `(:test)` methods in the PRG.
- Unit-test coverage was expanded for the new wrapper/helper layer so the recent refactors are not only compile-safe: there are now direct tests for the model-service facade, persistence save/restore, typed profile/score/card/event-log entries, settings support helpers, delegate input helpers, and the new persistence/render adapter types.
- Integration-style Garmin test coverage now also exists for the core operational flows: preset persistence across reinitialization, start/pause/resume plus paused restore, sanction persistence across save/restore, and the strict rugby-only recording startup contract.
- Game states: countdown sharing (minutes/seconds), conversion/penalty overlays, halftime, and finished.
- Conversion flow: recording a try automatically transitions the model into conversion state and the main view now auto-opens the conversion overlay on its next redraw instead of forcing that overlay directly from the nested score-menu callback. That removes a brittle `popView/popView/show overlay` handoff from the `MENU -> Score -> Try` path. The overlay now keeps the main countdown value at the top without a separate `COUNTDOWN` header, reserves the rest of the screen for the conversion timer/status copy, and intentionally hides yellow/red card timers while the overlay is active even though those sanctions continue running in the background. The bottom control hint is also shortened to a compact one-line prompt so the overlay stays visually cleaner on round Fenix screens.
- Menu access: a short `MENU` press still opens the in-app match menu. The in-match `Settings` action now opens the actual settings stack rather than a preset picker, and the old held preset shortcut path has been removed from the live UI flow.
- Countdown layout: the main countdown now keeps the same vertical anchor before kickoff and after play starts, so the large timer no longer shifts downward when the match begins.
- Conversion and penalty timers stay synchronized with the main countdown because they are both driven from the same pauseable `gameTime` clock, while the top count-up clock is driven from `elapsedTime` and continues running even while the main match countdown is paused. Kickoff no longer opens a timed overlay, so play resumes directly after conversion handling.
- Countdown rendering now uses one shared display-rounding helper for the main countdown, special overlay, and inline conversion/penalty labels so the special timers do not appear to trail the main clock by a second on different screens.
- Card stacks: new cards for the same team are stacked directly beneath the existing timer in label order (`Y1`, `Y2`, ... and `R1`, `R2`, ...), but only the first two active sanctions per team are shown at once. Any additional timers remain hidden until a visible timer expires, while still counting down in the background. Yellow and red timers use the same compact card font, shared row spacing, and the same display-rounding helper as the main countdown so they stay visually in sync. Under the hood, sanction timers now derive from the same `suspensionTime` phase instead of a mix of wall-clock timestamps and cached `remaining` values, which removes the pause/resume drift that was showing up when cards were issued during stoppages. Yellow timers vibrate once at <=10 seconds and again when one or more cards expire during the same update cycle. All timers reset on “Reset Game” or game completion.
- Discipline timing: yellow-card timers now stay live through halftime so added dead time after the 7-minute/40-minute horn still counts toward the suspension. The only variant that uses sevens-style card sanctions is a 7-minute half configuration: that case uses a 2-minute yellow and a permanent red. All other variants use a 10-minute yellow and a 20-minute timed red replacement window. Recording a yellow or red card now forces the match into the paused state first, because cards are administered while time is off. When the referee explicitly pauses the clock, both yellow-card timers and timed red-card timers freeze with the main countdown and resume from the same remaining time when play restarts, including cards that are logged while the match is already paused. The suspension timers are driven from absolute timestamps rather than frame deltas, and newly created paused cards are seeded with the current main-clock fractional phase so their displayed second changes line up with the main countdown when play resumes.
- Haptics: the watch now uses distinct patterns for match start, pause, resume, a repeating pause reminder every 5 seconds while the match is paused, half-time, full-time, lock toggle, conversion start/10-second warning/expiry, penalty start/10-second warning/expiry, and yellow-card warning/expiry so referees do not need to stare at the screen continuously.
- Settings: `Profile`, `Format Family`, and the new `Team Labels` preset are idle-only and are now enforced in the settings delegate rather than by constructor-time item flags, `Lock on Start` applies at the start of each half, and manual timer or team-label edits promote the active profile to the persistent `Custom` preset automatically. `Match Format` now opens an explicit preset chooser (`7s`, `10s`, `15s`, `U19s`), and half length is changed directly from the idle screen. The root settings menu still builds from the current live profile values, but inline rows now safely refresh their subtitles in place so on-watch feedback stays visible at the current cursor position.
- Performance note: the lightweight `Profiler` helper exists for targeted debugging only and is disabled by default so normal app runs do not spend time or memory on per-update profiling bookkeeping.
- Warning-reduction note: the newly touched settings/profile/event-log/card/render paths were cleaned to avoid adding more container-analysis noise. The current local validation path is back to clean app and test builds after the short renderer follow-up pass.
- Refactor note: the highest-value safe cleanup after the service split was consolidating duplicated clock math into `RugbyTimeMath`. That reduces the chance that pause syncing, live ticking, and persisted snapshot restoration drift apart when future timing rules change.
- Transition-note: the next behavior-preserving cleanup was moving match-state decision rules into `RugbyMatchStateSupport`. That keeps state checks consistent across delegate input, scoring-triggered special phases, clock resume behavior, and persisted paused-state restoration without changing the side-effect ownership.
- Event log: Every scoring or card event logs a human-readable string with `System.getTimer()` timestamps and appends to `lastEvents`. Those entries now use the active resolved team labels instead of hard-coded `Home` / `Away` strings, and the BACK/LAP dialog still exposes the Event Log view and a “Save log” action that persists the list to Storage for post-match sharing.
- Runtime status surfacing: one-shot status notices are now shared across recording failures, save failures, invalid saved-match recovery, and guarded input exceptions so operational problems are visible on-watch instead of only in `System.println`.
- GPS tracking: When the match starts, the app now attempts to open an `ActivityRecording` session with `SPORT_RUGBY` only. There is no generic-sport fallback anymore. On devices or runtime environments that do not support rugby activity recording, the match timer still runs normally without crashing, but no recording session is created. That unsupported/failure state now raises a short one-shot UI message in addition to the debug log path. If the referee leaves the app mid-match, the current recording segment is saved on stop and a new segment begins if play later resumes.

## Persistence & Release Notes
- `resources/drawables/` now includes a 40×40 launcher icon referenced in `resources/drawables/drawables.xml` and the manifest; replace it only with same-size assets to avoid scaling warnings.
- Non-runtime reference PNG assets that are not consumed by the Connect IQ build now live under `docs/assets/` instead of the repo root so the top-level tree stays focused on source, tests, resources, and release docs.
- Every change touching gameplay logic must be committed separately, and the release flow includes documentation updates in `docs/process/log.md` + `docs/architecture/project_technical_document.md`.
- `bin/rugbytimer.prg` should be rebuilt via `monkeyc` after every source change, and the path to `monkeyc.exe` (shown in `AGENTS.md`) must be captured in `docs/process/log.md`.
- Local validation can now run through `scripts/validate-local.sh`, which builds the app PRG and the unit-test PRG in one step before printing or invoking the correct `monkeydo <prg> <device_id> -t` command.
- Release automation runs through `.github/workflows/build_and_publish.yml`, which downloads the same SDK, invokes `monkeybrains.jar`, creates a GitHub release, and uploads the PRG to the Connect IQ Store whenever `CONNECTIQ_STORE_TOKEN` is set.
- The current maintenance plan is documented in `docs/MAINTENANCE_ROADMAP.md`, and the manual release/regression checklist is kept in `tests/README.md` so automated and manual validation stay close together.
